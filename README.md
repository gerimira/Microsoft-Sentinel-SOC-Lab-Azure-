# 🔐 Microsoft Sentinel SOC Lab (Azure)

## 📌 Overview

This project demonstrates a **hands-on Security Operations Center (SOC) lab** built in a personal Azure environment using **Microsoft Sentinel**. The goal was to gain practical experience with log ingestion, KQL analytics, incident creation, and MITRE ATT&CK mapping — aligned with real-world SOC analyst responsibilities.

This lab simulates how cloud activity can be monitored, detected, and investigated using SIEM principles.

---

## 🧱 Environment

* **Cloud Provider:** Microsoft Azure
* **SIEM:** Microsoft Sentinel
* **Log Analytics Workspace:** `lawlab2207new`
* **Account Type:** Personal Azure Lab
* **Access Role:** Owner (RBAC)

---

## 🔗 Data Sources

The following data source was configured:

### Azure Activity Logs

* Connected directly to Microsoft Sentinel
* Captures control-plane activity such as:

  * Resource creation/modification
  * VM start/stop operations
  * Resource group changes
  * Subscription-level actions

This connector was used to ensure immediate log ingestion without deploying agents.

---

## 🔍 Detection Engineering

### Custom Analytics Rule

A **Scheduled Query Rule** was created to detect suspicious or noteworthy Azure resource activity.

**Rule Name:**

> Suspicious Azure Resource Activity

**Logic (KQL):**

```kusto
AzureActivity
| where OperationNameValue contains "write"
| where ActivityStatusValue == "Succeeded"
| project TimeGenerated, Caller, OperationNameValue, ResourceGroup, SubscriptionId
```

**Configuration:**

* Query frequency: Every 5 minutes
* Lookback period: 1 hour
* Threshold: Results > 0
* Incident creation: Enabled

---

## 🚨 Incident Management

* Alerts generated by the analytics rule automatically create incidents
* Incidents are grouped by **Caller** to reduce alert noise
* Each incident includes:

  * Timeline of events
  * Raw AzureActivity logs
  * Associated entities

## 🧪 Simulation & Testing

To trigger detections, the following actions were performed:

* Creating and modifying Azure resources
* Executing VM and resource group changes

These actions successfully generated Sentinel incidents, validating detection logic and workflow.

## 🧠 MITRE ATT&CK Mapping

The analytics rule was mapped to the following MITRE ATT&CK tactics:

* **Persistence**
* **Impact**

This reinforces structured threat detection and aligns alerts with industry-standard adversary behavior models.
